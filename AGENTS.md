4. Run available tests, build, and affected user-flow checks before merge or production deploy.
5. Verify the Vercel team, project, target environment and deployment result before publishing. Do not claim a release without a verified URL.
6. Never commit secrets, tokens, private user data, .env files or credentials.
7. Require owner approval for auth, database, personal data, payments, billing, AI correctness, dependencies, destructive changes, and security-sensitive releases.
8. Small UI and copy changes may only be automated once tests, safe rollout, and rollback are in place and passing. No untested autonomous deployments.
9. If source code, credentials, or integration permissions are missing, report the blocker rather than inventing the missing source.
10. Give a brief German handoff: files changed, tests run, commit/PR, deployed URL if applicable, blockers.
